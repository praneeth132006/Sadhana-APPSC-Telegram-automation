Post to Telegram Now

Posting…

Posts go to the forum topic configured for the subject in the Config tab. Each question is sent as a quiz poll plus a spoiler-tagged answer, paced to stay inside Telegram's rate limits. Rejected and Archived questions are never eligible.

A question is reserved before it is sent, so a poll that reaches Telegram without a reply is never sent twice. Anything left unresolved shows as Sending in the Question Bank and waits for you rather than going out again.

Telegram never tells the bot when a message is deleted. This checks every posted question is still in the channel and offers to put the deleted ones back in the queue.

Puts every subject tab in this group back to the standard layout — header style, column widths, frozen panes, the dropdowns and the colour coding for Status, Posted and Difficulty. Use it if a tab has come out bold white on navy from top to bottom. It changes formatting only: not one question is touched.

Queue for Later

Marks questions Scheduled with a target time so the cron run picks them first

Queueing sets Status = Scheduled and fills the Scheduled For column. It does not post anything by itself — autopilot below, node schedule.js, or the button on the left does the sending.

Unqueueing is the way back: it takes the same number of queued questions, sets them to Approved and clears their Scheduled For time. They stay eligible to post — nothing is deleted, and a question already sent or being sent is never touched.

Autopilot

Posts a batch every few minutes, on its own, until the queue runs out

Each run does exactly what the Post button does: reserve the rows first, send each poll, then mark the sheet — so a question is never sent twice, and a run that fails halfway hands back what it did not send. Runs never overlap, and the next one is timed from when the last one finished.

Starting a subject that is already on autopilot just changes its settings — it does not start a second job.

⚠️ This deployment does not keep a job between requests, so the timer here will not fire. Point a scheduled job at /api/cron/autopilot to drive it.
